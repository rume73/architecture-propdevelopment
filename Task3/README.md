# Требования к внешним интеграциям (Smart Home)

## 1. Требования к безопасности

| № | Категория | Требование |
|---|-----------|------------|
| 1 | Конфиденциальность | Все данные передаются через **TLS 1.3** (при передаче) и хранятся с **AES-256** (на стороне партнёра). |
| 2 | Минимизация данных | Партнёр получает только **ID и метаданные**, не полные ПДн (ФИО, паспортные данные). |
| 3 | Биометрия | Хранение биометрических данных (лицо, номер автомобиля) — **только на стороне партнёра**. PropDevelopment не хранит и не передаёт сырые биометрические данные. |
| 4 | Изоляция сегментов | Интеграция проходит через **DMZ и API Gateway**. Партнёр не имеет прямого доступа к CRM и внутренним БД. |
| 5 | Логирование | Все API-вызовы журналируются (время, пользователь, действие, результат). Хранение — не менее 6 месяцев. |
| 6 | Отказоустойчивость | При недоступности партнёра система переходит в **безопасный режим** (шлагбаум открывается только по физическому ключу) и уведомляет администратора. |

## 2. Протоколы аутентификации и авторизации

| Протокол | Где используется | Требование |
|----------|------------------|------------|
| OAuth 2.0 / OpenID Connect | Аутентификация собственников в мобильном приложении | Использовать **Authorization Code Flow + PKCE** для мобильных приложений. Токены — **JWT** (15–30 мин), refresh-токены. |
| mTLS (Mutual TLS) | Взаимодействие с внешним API партнёра | Обе стороны подтверждают подлинность через **взаимные сертификаты** (защита от MITM-атак). |
| API Key + HMAC | Подпись запросов к партнёру | Каждый запрос подписывается через **HMAC-SHA256**. Это исключает подделку запросов. |
| RBAC / ABAC | Авторизация внутри PropDevelopment | **RBAC** для сотрудников (администратор, оператор), **ABAC** для собственников (доступ зависит от квартиры, дома и устройства). |

## 3. Организация взаимодействия между системами

| Аспект | Описание |
|--------|----------|
| Архитектурный паттерн | **API Gateway + BFF**. Мобильное приложение → API Gateway → smart-home-gateway-app / tenant-core-app. |
| Тип интеграции | **Синхронная (REST/JSON)** для команд (открыть дверь, шлагбаум) + **асинхронная (Webhook/Kafka)** для событий (распознавание лица, номер в белом списке). |
| Единая точка входа | `smart-home-gateway-app` — единственный сервис, взаимодействующий с партнёром. |
| Идентификация пользователя | Пользователь аутентифицируется через **OIDC**. API Gateway проверяет JWT и передаёт `user_id` и `claims` в gateway-сервис. |
| Маппинг данных | Внутренние ID (`owner_id`, `apartment_id`) транслируются во внешние ID партнёра (`device_id`, `resident_id`). |
| Обработка ошибок | Единый формат ошибок (**RFC 7807**). При ошибках партнёра — **ретраи** с экспоненциальной задержкой и **circuit breaker**. |
| Контракты API | Все контракты в **OpenAPI 3.0 (Swagger)**. Перед внедрением — автоматизированная проверка на наличие ПДн. |
